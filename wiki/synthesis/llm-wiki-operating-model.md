# llm-wiki-operating-model (LLM WIKI 운영 모델과 지식 생애주기)

## 한 줄 요약

LLM WIKI는 모델을 재학습시키는 저장소가 아니라, 원본 자료와 정리된 지식을 Obsidian 파일로 축적하고 Codex가 필요한 범위만 검색·갱신하게 하는 외부 지식 베이스다.

## 역할 분담

| 구성 요소 | 역할 |
|---|---|
| Obsidian | Markdown 파일을 읽고 링크·그래프를 탐색하는 작업 공간 |
| Codex | 원본 ingest, 분류, 요약, 링크 연결, 점검, 질문에 필요한 페이지 검색 |
| `AGENTS.md` | Codex가 위키를 다루는 운영 규칙과 작업 절차 |
| Git | Vault 전체의 변경 이력, 복구, 백업 및 협업 |

## 대화에서 정리된 운영 원칙

### 1. 새 채팅은 위키 전체를 자동으로 기억하지 않는다

새 채팅에서 Codex가 위키를 사용하려면 `wiki/overview.md`, `wiki/index.md`와 질문에 직접 관련된 페이지를 읽도록 요청해야 한다. Vault에 파일이 존재한다는 사실만으로 모든 문서가 현재 대화 문맥에 들어오지는 않는다.

### 2. 토큰 사용량은 ‘추가된 문서’만으로 결정되지 않는다

실제 문맥에 포함되어 읽힌 텍스트의 양과 작업 방식에 따라 토큰 사용량이 달라진다. 새로 추가된 파일만 읽으면 그 범위만 비용에 반영될 수 있지만, Codex가 기존 문서나 여러 출처를 함께 읽으면 해당 내용도 포함된다. 제품별 정확한 과금·문맥 처리 방식은 시점과 설정에 따라 확인이 필요하다.

### 3. 위키가 모델 자체를 영구적으로 학습시키는 것은 아니다

위키를 사용한다고 Codex의 가중치나 일반 능력이 자동으로 바뀌지는 않는다. 대신 출처가 정리되고, 페이지 간 링크가 쌓이고, 다음 대화에서 필요한 자료를 더 정확히 꺼내 쓰게 되면서 작업 품질이 누적될 수 있다. 이 효과는 모델의 ‘복리 학습’이라기보다 검색·구조화·재사용의 복리 효과에 가깝다.

### 4. 대화도 재사용 가치가 있으면 정리해서 저장한다

대화 원문 전체를 쌓기보다 다음을 추려 저장한다.

- 반복해서 사용할 운영 원칙
- 여러 주장을 비교한 표와 판단 기준
- 출처와 불확실성이 표시된 분석
- 다음 조사를 위한 미해결 질문

### 5. 파일은 Codex에게 맡겨 분류할 수 있다

사용자가 파일을 제공하고 반영을 요청하면 원본을 `raw/sources/`에 보존하고, 주제와 재사용 목적에 따라 `wiki/sources/`, `concepts/`, `entities/`, `queries/`, `comparisons/`, `synthesis/`로 분류한다. 중복 페이지를 만들기보다 기존 페이지를 갱신하고 출처와 링크를 추가하는 것을 우선한다.

### 6. Raw와 Wiki는 분리한다

`raw/`는 사람이 수집한 원본이고, `wiki/`는 출처를 바탕으로 합성한 지식이다. 원본은 명시적인 삭제 요청 없이는 덮어쓰거나 삭제하지 않는다. 지식 페이지는 주기적으로 중복·오래된 주장·고립 링크를 정리하되, 원본과 변경 이력은 남긴다.

### 7. `AGENTS.md`는 지식 노트가 아니다

`AGENTS.md`에는 분류 규칙, 작성 형식, 검증 절차처럼 Codex가 계속 따라야 할 운영 지침을 기록한다. 개별 주제의 사실·전망·대화 분석은 `wiki/` 아래의 일반 페이지로 저장한다.

## 권장 흐름

```text
원본 또는 대화
  → 출처·주제·재사용 가치 확인
  → raw 보존 또는 질문/분석 정리
  → 적절한 Wiki 페이지 생성·갱신
  → Wikilink·인덱스·로그 갱신
  → Obsidian에서 검토
  → Git 커밋 및 원격 저장소 백업
```

## 정리 기준

- 원본은 보존하고, 합성 페이지는 중복을 줄인다.
- 확정 사실·해석·가설·확인 필요 항목을 구분한다.
- 시점에 따라 바뀌는 내용은 `updated`와 확인 날짜를 남긴다.
- 출처 없는 예측은 사실처럼 쓰지 않는다.
- GitHub에 올릴 때는 API 키, 토큰, 개인 정보가 포함되지 않았는지 먼저 확인한다.

## 논쟁과 한계

이 문서는 Codex와 Obsidian을 사용하는 현재 작업 방식에 대한 운영 합의다. Codex의 문맥 처리, 토큰 계산, 파일 접근 권한, GitHub 연동 방식은 제품과 설정에 따라 달라질 수 있으므로 제품별 세부 동작은 필요할 때 공식 문서로 다시 확인해야 한다.
